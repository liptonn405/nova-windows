# Архитектура NOVA Windows

## Поток запроса

1. Интерфейс принимает текст или подтверждённое распознавание речи.
2. `intents.py` сопоставляет известные команды с типизированным действием. Это быстрый путь без модели.
3. Обычное общение идёт в локальный Ollama API с ограниченным контекстом и потоковым выводом.
4. Кнопка «План» запрашивает JSON, полностью валидирует его, затем показывает подтверждение. Без подтверждения ни одно действие плана не выполняется.
5. `agent.py` диспетчеризует только разрешённые инструменты. `windows.py` обращается к Win32, Core Audio, SMTC и виртуальным столам; проверяет результат там, где это поддерживается.

Модель не пишет исполняемый код. Передача JSON в subprocess отсутствует. PowerShell используется только для фиксированного чтения списка приложений, без вставки пользовательского текста. Запуск приложений использует пути, полученные из регистрации Windows и ярлыков.

## Модули

| Файл | Назначение |
|---|---|
| `app.py` | Qt UI, очередь фоновых задач, настройки, трей, таймеры |
| `pet.py`, `behavior.py` | Рисование и независимая от FPS анимация |
| `monitor.py` | Батарея, медиасессия, амплитуда звука |
| `intents.py` | Русские команды без LLM |
| `policy.py` | Схема инструментов, валидация, границы рабочей папки |
| `agent.py` | Выполнение и планирование |
| `windows.py` | Нативные адаптеры Windows |
| `ollama.py` | Локальный HTTP, поток, отмена, выгрузка выбранной модели |
| `voice.py` | SAPI и Vosk по кнопке |
| `config.py` | Типизированные настройки, атомарная запись JSON |

## Жизненный цикл

Главный поток только рисует и обрабатывает UI. Запросы модели, распознавание и команды запуска выполняются в рабочих потоках. Ответы передаются Qt-сигналами; поздние ответы отменённого запроса отбрасываются. Одновременно допускается одна пользовательская задача. Обновление списка моделей работает отдельно.

Выход из чата устанавливает отмену. Текущий HTTP-поток закрывается при следующей порции данных либо сетевом тайм-ауте; затем отправляется `keep_alive: 0` для выбранной модели. Глобальная служба Ollama не уничтожается. Для прогретого режима между запросами используется 10 минут, но явный выход из чата запрашивает выгрузку независимо от переключателя.

Смена фокуса не является событием закрытия. Глаза и другие автономные реакции продолжаются независимо от окна чата. Наушники и глаза используют общий transform. Монитор получает реальную амплитуду устройства, а не синтетическую анимацию под случайный ритм.

Файлы читаются только относительно выбранной папки (исходно Documents/NOVA), с проверкой выхода через `..`, абсолютные пути и symlink. Ограничение чтения: 64 КБ и текстовые расширения. Создание заметок использует режим `x`: существующие файлы не меняются.

## Что добавлять дальше

Следующие расширения требуют отдельных адаптеров и тестов: подтверждённый лайк Яндекс Музыки через поддерживаемый API, доступ к календарю, анализ выбранного скриншота, потоковая нейросетевая TTS. Не подключать эти функции выдачей модели произвольного shell-доступа. Новый инструмент сначала описывается в `SCHEMA`, затем реализуется в адаптере, тестируется и добавляется в подсказку планировщика.
